### 一句话总结

Sketch-Omni 通过自动构造照片—草图监督与 photo-guided relation alignment，将 Rex-Omni 扩展为支持草图内感知和草图查询照片实例的统一模型，在 FS-COCO 的 instance-level visual prompting 上达到 91.4 F1@0.5，但尚未验证单源域检测器对未知真实目标域的泛化。

### 问题与动机

论文处理草图与照片之间的两类感知问题：一是在草图中执行 detection、pointing、object referring、spatial referring 和 affordance grounding；二是将单个对象的草图作为查询，在照片中定位其对应实例，尤其区分同类别的多个对象。

作者认为，现有照片感知模型存在两个障碍：

- **外观依赖造成模态偏移。** 照片模型依赖颜色、纹理，其 phrase-to-patch 和 patch-to-patch 关系迁移到稀疏线条后容易失效，注意力可能落在空白区域；即使找到大致区域，也难以输出贴合笔画的边界框。
- **实例级监督不足。** 现有草图数据主要提供单对象草图—照片配对、无框场景草图或检索得到的实例链接，缺少“这幅草图对应复杂照片中的哪一个对象”的可靠训练标注。

这里的关键区别是 **instance-level 查询**：category name 通常选择整个类别，而草图可以通过形状表达特定实例。论文希望把这种能力纳入统一的坐标 token 接口，同时避免新增人工训练标注。

### 方法要点

- **保留 Rex-Omni 的统一接口，用 LoRA 扩展草图能力。** 基座为 Qwen2.5-VL-3B，冻结原始权重，在语言模型各 block 的全部 linear layers，以及 vision encoder 的 query、key、value、output projections 上训练 rank-64 LoRA；坐标离散为 1000 个 bins，以 next-token prediction 输出框或点。

- **Stage A：从照片自动继承草图监督。** 用 HED 将 Objects365、RefCOCOg、AGD20K 照片转换为像素对齐的 edge sketches，继承检测框、指代表达和 affordance 标签。对于草图无法表达的颜色、纹理词，先用词典过滤，再仅对被修改的表达调用基座模型重新 grounding，因此部分标签属于模型生成的伪标签。

- **对齐结构关系，而非直接对齐特征。** 冻结的照片路径提供教师信号，LoRA 草图路径学习两类关系：phrase query 到所有 visual keys 的 cosine similarity，以及前景 visual queries 之间的 cosine similarity。前者约束表达选择正确区域并抑制空白响应，后者约束对象内部结构；在每个 decoder layer、每个 head 上匹配，权重为 \(\lambda_{\mathrm{cross}}=0.5\)、\(\lambda_{\mathrm{intra}}=0.25\)。Stage A 每步额外需要一次无梯度照片前向。

- **Stage B：用两种构造补足实例级查询数据。** 一种将 Sketchy 配对照片与同类别干扰对象拼接，让手绘草图指向唯一实例；另一种从 Objects365 照片的 HED 图中裁出某个对象，再要求模型在原照片中定位它。前者提供真实绘画风格变化，后者提供复杂场景中的精确形状对应。

- **交替多任务训练，再以 GRPO 优化定位。** Stage A 与 Stage B 按 2:3 的比例、以 50 optimiser steps 为块交替；Stage B 还加入 QuickDraw、TU-Berlin、Sketchy 合成场景的 detection 和 pointing，并以 `None` 回答不存在的类别。最后所有配置均经过同样的 GRPO refinement。双图输入时，vision encoder 对照片禁用 LoRA、对草图启用 LoRA，语言模型则在整个序列上启用。

### 实验

**数据与评测设置。** 训练使用 Objects365、RefCOCOg、AGD20K、Sketchy，以及来自 QuickDraw、TU-Berlin、Sketchy 的合成手绘场景。instance VP 在 1340 个 SketchyCOCO queries 和 2754 个 FS-COCO queries 上评测；FS-COCO 的草图框和 sketch-to-photo instance links 为新增人工评测标注。作者对 SketchyCOCO 做了类别和草图实例级重叠过滤。

Detection、referring 报告 F1@0.5、F1@0.9 和 F1@avg；其中 avg 是 IoU 从 0.5 到 0.95、步长 0.05 的均值，**不是常规 COCO AP**。Pointing 与 affordance 根据预测点是否落入目标区域计分。

**instance-level sketch VP 主要结果：**

| Method | SketchyCOCO F1@0.5 | FS-COCO F1@0.5 | FS-COCO F1@0.7 |
|---|---:|---:|---:|
| Qwen2.5-VL-3B | 53.6 | 51.1 | 47.5 |
| Qwen3-VL-8B | 66.5 | 81.8 | 76.9 |
| MiMo-VL-7B | 61.2 | 45.5 | 40.1 |
| DeepSeek-VL2-S | 50.3 | 36.0 | 26.0 |
| Rex-Omni | 13.0 | 4.0 | 1.4 |
| G-DINO + ZSE-SBIR | 63.3 | 51.1 | 47.1 |
| Sketch-Omni w/o align | 69.8 | 88.6 | 84.2 |
| Sketch-Omni full | **71.0** | **91.4** | **87.1** |

Rex-Omni 原本接收目标图内部的 reference boxes，并不具备同等的双图实例查询接口，因此其低分同时反映了接口与任务不匹配，不能单独作为草图表征能力的证据。与接收相同两张图的 Qwen3-VL-8B 比较更有解释力。

**同类别干扰分析，指标为 F1@0.5：**

| Method | SketchyCOCO Easy | SketchyCOCO Hard | FS-COCO Easy | FS-COCO Hard |
|---|---:|---:|---:|---:|
| Qwen3-VL-8B | 90.2 | 47.8 | 84.3 | 63.1 |
| Sketch-Omni | 89.5 | 51.4 | 92.7 | 80.3 |
| 原文报告的差值 | -0.7 | +3.6 | +8.4 | +17.2 |

Easy 表示照片中只有一个该类别实例，Hard 表示有两个或更多。FS-COCO Hard 上优势明显扩大，支持“草图提供实例形状信息”的解释；但 SketchyCOCO Easy 上模型并未超过 Qwen3-VL-8B。

**草图输入任务的代表性结果：**

| Task / 数据集 | 指标 | Sketch-Omni | 对照 |
|---|---|---:|---|
| Detection / FS-COCO | F1@0.5 | 86.7 | Rex-Omni：80.0；Qwen3-VL-8B：75.3 |
| Detection / FS-COCO | F1@0.9 | 65.7 | Rex-Omni：56.1；Qwen3-VL-8B：23.0 |
| Detection / COCO HED | F1@avg | 36.0 | Qwen3-VL-8B：27.5 |
| Pointing / FS-COCO | F1@Point | 89.9 | Rex-Omni：84.9 |
| Pointing / COCO HED | F1@Point | 44.5 | Qwen3-VL-8B：47.9 |
| Object referring / RefCOCOg test HED | F1@0.5 / F1@0.9 | 74.6 / 42.7 | DeepSeek-VL2-S：66.1 / 25.9 |
| Spatial referring / RefCOCOg test HED | F1@0.5 / F1@0.9 | 76.7 / 43.1 | DeepSeek-VL2-S：65.1 / 20.2 |
| Affordance / AGD20K Seen | Point-in-region F1 | 66.2 | Rex-Omni：51.3 |
| Affordance / AGD20K Unseen | Point-in-region F1 | 74.3 | Rex-Omni：61.0 |

**消融与机制证据。** 去掉 alignment 后，构造数据本身已经使 instance VP 超过所有基线；加入 alignment 后，六个 instance VP 单元均进一步提升，原文报告增益为 0.9 至 2.9。作者还报告 alignment 在全部 14 个消融单元中均有效，referring 最多提升 4.3 F1，但给定正文未包含 Appendix F 的完整数表。

可视化显示，完整模型的 phrase-to-patch 响应更集中于目标，patch-to-patch 响应更能沿对象传播；高 IoU 下的表现也支持定位精度改善。不过，独立移除 cross-modal loss、intra-modal loss，以及两类 instance VP 数据的数值消融，给定内容未说明。

### 与你研究的关系

这篇论文与你的研究有较强的**方法层面关联**，但并非 single-domain generalization object detection 工作：它使用多个照片与草图数据源，显式训练草图模态，未评估检测器在未知天气、城市或成像风格等真实目标域上的泛化。

最值得借鉴的是以下几点：

- **以保持几何结构的转换继承检测标签。** 照片到 HED sketch 不改变像素坐标，避免了生成式风格迁移可能引入的对象形变和框错位。可将其作为单源检测训练中的结构视图，但不能据此认定小目标细节得到保留。
- **将关系蒸馏用于跨外观一致性。** 原图作为冻结教师、增强图作为学生，约束 phrase-region 和 object-internal relations，同时允许特征随外观变化。这为风格增强后的语义、定位一致性提供了比直接 feature matching 更有针对性的设计。
- **用严格定位与困难子集检验泛化机制。** F1@0.9 和同类别干扰子集，比单一宽松阈值更能揭示“找到大致区域”与“精确保持边界”的区别，适合借鉴到风格转换后的框保持评测。
- **保留小目标与边界的需求仍待补足。** 文中按最终尺寸直接渲染矢量笔画，以维持笔画宽度；但 Objects365 的 HED query 构造跳过面积小于 \(96\times96\) pixels 的框。这使其对小目标鲁棒性的证据尤其有限。

复现方面，3B 基座与 LoRA 有利于控制可训练参数规模，但完整训练仍使用 32 H100 GPUs，并不直接符合低算力复现偏好。

### 局限与可追问点

- **未知域泛化尚未建立。** HED 是明确参与训练的模态，Stage B 又包含真实手绘数据；手绘测试结果不能被解释为仅用单一照片源域即可泛化到未知风格。值得验证：仅使用源域照片及其转换视图时，relation alignment 是否仍改善真实跨域检测。

- **结构保持不等于信息完整。** HED 可能遗漏细线、弱边界与小对象；框坐标可原样继承，并不保证框内仍有足够识别证据。文中未报告按目标尺寸划分的结果、边缘缺失压力测试或小目标失败案例。

- **评测的真实性不均衡。** Detection 和 pointing 包含真实 free-hand sketches，但 referring 与 affordance 仅在 HED sketches 上评测；这两类能力对真实手绘抽象、位置偏差和笔画缺失的鲁棒性仍待确认。SketchyCOCO 的链接则来自检索，作者也承认其标签与显著性偏差。

- **合成任务可能包含容易利用的对应线索。** Objects365 query 直接来自目标照片的边缘裁剪，拼接画布又保证对象区域完整可见。值得测试独立凭记忆绘制的查询、严重遮挡、视角改变和几何变形，区分精确形状匹配与更抽象的实例理解。

- **关键组件归因不足。** 当前可见消融主要支持整体 alignment 有效，尚不能分离两项关系损失、两类构造数据、手绘合成场景与 GRPO 的贡献；也缺少与直接 feature distillation 的定量对照。

- **失败分析主要针对基线。** 正文列出基线误选同类别干扰项、显著对象或无输出的情况，但没有系统整理 Sketch-Omni 自身的失败分布，例如高度相似实例、抽象草图或多解查询。

- **算力与资源可用性限制复现。** 监督训练约 1 day on 32 H100 GPUs，GRPO 约 8 hours on 32 H100 GPUs；低算力配置、推理延迟、显存和训练数据总量文中未说明。代码与模型尚无给定链接。
